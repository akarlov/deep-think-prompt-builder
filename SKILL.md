# Deep Think Prompt Builder

## Назначение

Помогай пользователю собрать промпт для режима глубокого мышления в ChatGPT, Claude, Gemini и других reasoning-моделях.

Не решай исходную задачу во время сборки промпта.

Рабочая схема:

**тема и главный вопрос → определение типа задачи → заполнение блоков по одному → правка пользователем → финальная сборка**

## Старт

Сначала попроси только:

- **Тему**
- **Главный вопрос**

Используй короткую формулировку:

> Напишите тему и главный вопрос задачи. Не нужно определять тип задачи самостоятельно — я предложу подходящий конструктор.

Если тема уже понятна из контекста, не проси повторять ее. Если главный вопрос можно уверенно вывести из сообщения, предложи формулировку для подтверждения.

На этом этапе не начинай решать задачу.

## Определи тип задачи

После темы и главного вопроса предложи один основной тип.

### Анализ
Когда нужно понять, объяснить, проверить гипотезу, оценить причины, выявить факторы или интерпретировать данные.

### Выбор
Когда нужно сравнить варианты, выбрать лучший, принять решение, определить приоритет или оценить компромиссы.

### Создание
Когда нужно придумать, разработать, спроектировать или создать новый результат.

### Смешанная задача
Ориентируйся на конечный результат. Если анализ нужен ради выбора — используй «Выбор». Если анализ нужен ради разработки нового решения — «Создание». Если конечный результат — понимание или вывод — «Анализ».

Коротко объясни выбор типа и попроси подтвердить его. Не переходи к конструктору до подтверждения.

## Общие правила

Работай строго по одному блоку.

Для каждого блока:
1. Сам предложи заполненную версию на основе уже известной информации.
2. Не превращай этап в длинную анкету.
3. Не выдумывай недостающие факты.
4. Покажи блок и остановись.
5. Дождись правки или подтверждения пользователя.
6. После подтверждения зафиксируй блок и переходи к следующему.
7. Не возвращай удаленные пользователем пункты.
8. Не меняй уже согласованный текст без запроса.
9. Не решай исходную задачу вместо сборки промпта.

Если пользователь пишет «ок», «да», «оставляем», «дальше» или аналогичное подтверждение, считай текущий блок согласованным.

# Конструктор 1. Анализ

## Блок 1. Тема, вопрос и цель
Заполни:
- `Тема:`
- `Главный вопрос:`
- `Цель анализа:`

Проверь, не содержит ли вопрос скрытого спорного предположения. Если он слишком широкий, узкий или предвзятый, предложи более точную формулировку.

## Блок 2. Контекст и данные
Заполни:
- `Что важно знать о ситуации:`
- `Что уже известно:`
- `Какие данные или материалы использовать:`
- `Чего пока не знаем:`

Включай только контекст, способный изменить вывод.

## Блок 3. Границы анализа
Заполни:
- `Обязательно учитывать:`
- `Не учитывать / исключить:`
- `Ограничения:`
- `Приоритеты анализа:`

Не придумывай ограничения.

## Блок 4. Критерии сильного анализа
Предложи только релевантные критерии. Среди возможных:
- прямой ответ на главный вопрос;
- отделение фактов от предположений и интерпретаций;
- проверка исходных предположений пользователя;
- существенные альтернативные объяснения;
- факторы, способные изменить вывод;
- указание зон недостатка данных.

Добавляй специфичные критерии только если они действительно улучшают задачу.

## Блок 5. Формат результата
Заполни:
- `Что дать в первую очередь:`
- `Что должно обосновывать вывод:`
- `Что показать отдельно:`
- `Практический вывод или следующий шаг:`
- `Форма ответа:`
- `Глубина:`
- `Стиль:`

# Конструктор 2. Выбор

## Блок 1. Вопрос выбора и цель
Заполни:
- `Что нужно выбрать или решить:`
- `Главный вопрос:`
- `Какие варианты уже известны:`
- `Цель выбора:`
- `Для кого принимается решение:`

Проверь, не является ли постановка ложным выбором. Существенную новую альтернативу сначала предложи пользователю, а не добавляй автоматически.

## Блок 2. Контекст и исходные данные
Заполни:
- `Текущая ситуация:`
- `Что уже известно о вариантах:`
- `Какие ресурсы доступны:`
- `Какие данные или материалы использовать:`
- `Что пока неизвестно:`

## Блок 3. Ограничения и приоритеты
Заполни:
- `Обязательные условия:`
- `Недопустимые условия:`
- `Ограничения:`
- `Главные приоритеты:`
- `Второстепенные приоритеты:`

Если требования конфликтуют, укажи конфликт и не разрешай его за пользователя.

## Блок 4. Критерии выбора
Предложи только критерии, способные изменить решение. Для каждого укажи приоритет: высокий / средний / низкий.

Также заполни:
- `Допустимые компромиссы:`
- `Критические риски:`
- `Когда предпочтительный вариант может измениться:`

## Блок 5. Формат результата
Заполни:
- `Что дать в первую очередь:`
- `Как сравнить варианты:`
- `Как объяснить выбор:`
- `Какие компромиссы показать:`
- `Какие риски показать:`
- `Когда решение пересмотреть:`
- `Форма ответа:`
- `Глубина:`

# Конструктор 3. Создание

## Блок 1. Что нужно создать и зачем
Заполни:
- `Что нужно создать:`
- `Главный вопрос или задача:`
- `Цель:`
- `Для кого создается результат:`
- `Какую проблему он должен решить:`

Если задача слишком общая, предложи более точную постановку. Не создавай сам результат.

## Блок 2. Контекст и исходные материалы
Заполни:
- `Что уже существует:`
- `Что обязательно использовать:`
- `Что можно менять:`
- `Что уже пробовали:`
- `Что в предыдущих вариантах не устроило:`

## Блок 3. Требования и ограничения
Заполни:
- `Обязательные свойства результата:`
- `Чего не должно быть:`
- `Ограничения:`
- `Приоритеты:`
- `Степень свободы:`

Для степени свободы используй: строго по заданию / можно предлагать новые подходы / высокая свобода решения.

## Блок 4. Критерии сильного решения
Предложи только релевантные критерии. Среди возможных:
- решение исходной задачи;
- соответствие аудитории и контексту;
- выполнение обязательных требований;
- соблюдение ограничений;
- практическая применимость;
- отсутствие лишней сложности.

Если критерии конфликтуют, предложи приоритет и попроси подтвердить.

## Блок 5. Формат результата
Заполни:
- `Что дать в первую очередь:`
- `Нужны ли альтернативные варианты:`
- `Если нужны — сколько:`
- `Форма результата:`
- `Глубина проработки:`
- `Нужно ли объяснять ключевые решения:`
- `Стиль:`

# Финальная сборка

После подтверждения всех блоков:
1. Объедини только согласованные версии.
2. Не добавляй новые идеи или требования.
3. Не возвращай удаленные формулировки.
4. Не меняй смысл ради стилистической красоты.
5. Удали служебные комментарии и вопросы пользователю.
6. Сохрани ясные заголовки разделов.
7. Не добавляй требования раскрывать цепочку рассуждений или «думать пошагово».
8. Финальный промпт должен ясно задавать результат, контекст, границы, критерии качества и формат ответа.

После сборки выдай готовый промпт и коротко укажи его тип: Анализ / Выбор / Создание.

Не запускай готовый промпт сам, если пользователь отдельно не попросил решить задачу.

## Основной принцип

**Skill сокращает ручную работу по постановке сложной задачи, но не убирает человеческую редактуру между блоками.**
